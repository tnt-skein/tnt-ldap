# Вход через каталог LDAP

Каталог учётных записей — OpenLDAP, Active Directory, FreeIPA — знает
людей организации, их пароли и группы. `tnt-ldap` — клиент такого
каталога поверх сокета Tarantool и `tnt-tls`: вход паролем с удостоверением
и поиск записей, TLS всегда, а всё, что пришло от каталога негодным, —
отказ парой с родом.

```lua
local ldap = require('tnt.ldap')

local directory = ldap.new({
    url = 'ldaps://ldap.example.org',
    bind_dn = 'cn=readonly,dc=example,dc=org',
    bind_password = os.getenv('LDAP_READER_PASSWORD'),
    base = 'ou=people,dc=example,dc=org',
    filter = '(&(objectClass=inetOrgPerson)(uid={username}))',
    attributes = { 'memberOf', 'mail' },
    limiter = limiter,           -- счёт попыток до каталога: «Счёт попыток»
    limit = per_minute(5),
})

local assertion, err = directory:authenticate('anna', 'anna-secret')
```

## Зачем пакет

Готового клиента LDAP для Tarantool Community Edition нет: рок `ldap`
поставляется только с Enterprise Edition, а обёртка над системной
`libldap` ждала бы сети в потоке событий, и узел на это время стоял бы
целиком. Пакет говорит LDAPv3 сам — свой BER, пять операций клиента,
фильтр строкой — и ждёт сеть файбером. Вход паролем держится на пяти
решениях, и каждое закрывает свою дверь:

1. **Пустой пароль — отказ до каталога.** Простая привязка с DN и пустым
   паролем — привязка без проверки (RFC 4513, §5.1.2): каталог отвечает
   на неё успехом, и вход без пароля проходил бы под любым именем.
2. **Имя в фильтре экранировано** по RFC 4515, §3. Имя `*)(uid=*`,
   вставленное как есть, превращает поиск одной записи в поиск любой.
3. **TLS всегда.** Простая привязка несёт пароль открытым текстом
   (RFC 4513, §6.3.1): `ldaps://` шифрует с первого байта, `ldap://` —
   всегда StartTLS, открытого разговора нет вовсе.
4. **`subject` — постоянный признак записи**: `entryUUID` (RFC 4530),
   у Active Directory — `objectGUID`. DN меняется при переносе записи
   в другое подразделение и в опознаватель не годится; он и группы
   лежат в `claims`.
5. **Счёт попыток — до каталога.** У каталога своя политика запирания,
   и перебор со стороны узла запирал бы настоящих людей в самом каталоге.

О личности пакет не знает: он отдаёт удостоверение — кто вошёл, через
какой каталог и когда, — а учётную запись по нему находит само
приложение. Зависимости: [`tnt-tls`](https://github.com/tnt-skein/tnt-tls)
(шифрование), [`tnt-clock`](https://github.com/tnt-skein/tnt-clock) (часы
срока и миг входа), [`tnt-external`](https://github.com/tnt-skein/tnt-external)
(подмена сети и часов в проверках) и [`tnt-must`](https://github.com/tnt-skein/tnt-must)
(проверки аргументов). Ограничитель попыток приходит настройкой: пакет
зовёт у него два метода и зависимостью его не объявляет.

## Как пользоваться

| Действие | Что делает |
|---|---|
| `ldap.new(настройки)` | клиент каталога; в сеть не ходит |
| `каталог:authenticate(имя, пароль)` | вход паролем: удостоверение либо `nil, err` |
| `каталог:search({ base, filter, scope, attributes, size_limit })` | записи от имени служебной учётной записи либо `nil, err` |
| `ldap.escape(значение)` | значение для вставки в фильтр строкой |
| `MAX_MESSAGE` | предел сообщения каталога: 1 МиБ |
| `INVALID`, `THROTTLED`, `UNAVAILABLE`, `REJECTED`, `MALFORMED` | роды отказа |

Примеры ниже прогнаны на Tarantool 3.8.0 против OpenLDAP 2.4.57 стенда
(`make ldap-up`): у стенда свой адрес, `127.0.0.1` с портами 18636
и 18389, свой корень сертификата и свой `entryUUID` у каждой записи.

### Вход паролем

Вход — «найти, затем войти». Служебная учётная запись (`bind_dn`) ищет
запись посетителя фильтром из настроек, а пароль проверяет простая
привязка по найденному DN. DN из имени не собирается: у Active Directory,
у каталога с людьми в нескольких ветках и у входа по почте он из того,
что ввёл человек, не выводится.

```lua
directory:authenticate('anna', 'anna-secret')
--> {
-->     provider = 'ldap',
-->     subject = 'f2e3b24a-4d34-1041-90e9-03328628d0dc',
-->     name = 'Анна Петрова',
-->     methods = { 'pwd' },
-->     authenticated_at = 1790344751.2061,
-->     claims = {
-->         dn = 'uid=anna,ou=people,dc=example,dc=org',
-->         memberOf = { 'cn=operators,ou=groups,dc=example,dc=org' },
-->         mail = { 'anna@example.org' },
-->     },
--> }
```

За один вход — одно соединение: TLS, привязка служебной учётной записи,
поиск не больше двух записей, привязка найденного DN с паролем, отвязка.
Пароль проверяется и у неизвестного имени — привязкой к записи, которой
нет (`cn=tnt-ldap-absent,` и база поиска), — иначе ответ на неизвестное
имя приходил бы на один обмен раньше, и по времени было бы видно, какие
имена в каталоге есть. Слово отказа у обоих одно:

```lua
directory:authenticate('anna', 'wrong')
--> nil, { kind = 'invalid', message = 'неверное имя или пароль', code = 49, diagnostic = '' }
directory:authenticate('boris', 'x')
--> nil, { kind = 'invalid', message = 'неверное имя или пароль', code = 49, diagnostic = '' }
directory:authenticate('anna', '')
--> nil, { kind = 'invalid', message = 'неверное имя или пароль' }        -- до каталога
directory:authenticate('*', 'anna-secret')
--> nil, { kind = 'invalid', message = 'неверное имя или пароль', code = 49, diagnostic = '' }
```

Что ответил каталог, лежит в полях `code` и `diagnostic` — для журнала
оператора: Active Directory пишет в пояснение, заперта ли учётная запись
и истёк ли пароль (`data 775`, `data 532`), а человеку об этом не говорят.
Пустое имя и имя длиннее 256 байтов — тоже отказ до каталога. Имя
и пароль не строкой — бросок на строке вызова: их передаёт код.

Имя посетителя встаёт в фильтр вместо `{username}` — в каждое место,
где оно названо, — и только через `ldap.escape`. Фильтр из настроек
разбирается при сборке, поэтому `{username}` на месте имени атрибута —
бросок `new`, а не поиск, который молча никого не находит.

### Удостоверение

| Поле | Откуда |
|---|---|
| `provider` | настройка `name`, по умолчанию `ldap` |
| `issuer` | нет: ключ учётной записи — пара `provider` и `subject` |
| `subject` | первое значение атрибута `subject` (по умолчанию `entryUUID`) |
| `name` | первое значение атрибута `display` (по умолчанию `cn`); нет — пусто |
| `methods` | `{ 'pwd' }` (RFC 8176) |
| `authenticated_at` | миг входа по стенным часам |
| `claims` | `dn` и атрибуты настройки `attributes` списками значений; нет у записи — пустой список |

Имена атрибутов сверяются без учёта регистра (RFC 4512, §2.5): каталог
вправе ответить `memberof` на просьбу о `memberOf`, а в `claims` атрибут
лежит под тем именем, каким его назвали в настройках. Запись без
опознавателя, с пустым, длиннее 255 байтов (предел `sub` OpenID Connect
Core 1.0, §2) или с управляющим знаком в нём — отказ `malformed`: такой
`subject` не годится ключом учётной записи.

Роли из групп собирает приложение, когда находит учётную запись
по удостоверению: утверждения живут один вход и в учётную запись сами
не переходят.

```lua
local function resolve(assertion)
    local account = accounts.by_directory(assertion.provider, assertion.subject)

    if account == nil then
        return nil
    end

    local roles = {}

    for _, group in ipairs(assertion.claims.memberOf) do
        if group == 'cn=operators,ou=groups,dc=example,dc=org' then
            table.insert(roles, 'operator')
        end
    end

    return { id = account.id, name = assertion.name, roles = roles }
end
```

### Active Directory

`objectGUID` у Active Directory — 16 байтов, а не текст. Настройка
`subject = 'objectGUID'` пишет его текстом, как его показывают средства
Windows: первые три поля — младшим байтом вперёд,
`3f2504e0-4f89-11d3-9a0c-0305e82c3301`. Остальное — обычные настройки:

```lua
local directory = ldap.new({
    url = 'ldaps://dc1.corp.example.org',
    bind_dn = 'CN=svc-reader,OU=Service,DC=corp,DC=example,DC=org',
    bind_password = os.getenv('AD_READER_PASSWORD'),
    base = 'OU=People,DC=corp,DC=example,DC=org',
    filter = '(&(objectClass=user)(sAMAccountName={username})(!(userAccountControl:1.2.840.113556.1.4.803:=2)))',
    subject = 'objectGUID',
    display = 'displayName',
    limiter = limiter,
    limit = per_minute(5),
})
```

Последнее условие фильтра — сравнение по правилу: отключённые учётные
записи каталог не находит вовсе, и отказ им — тот же `invalid`.

### Счёт попыток

Счёт обязателен: ограничитель и предел, либо явное `limiter = false` —
тогда считает тот, кто зовёт `authenticate` (например, предел на маршруте
входа). Забыть о нём молча нельзя:

```lua
ldap.new({ url = 'ldap://ldap.example.org', base = '' })
--> бросок: настройки.limiter: счёт попыток обязателен — ограничитель tnt-throttle либо false
```

От ограничителя и предела пакету нужно по одному методу:

| Что | Вызов | Что пакет ждёт в ответ |
|---|---|---|
| `limit` | `limit:by(ключ)` | правило счёта для ключа; пакет отдаёт его `consume` как есть |
| `limiter` | `limiter:consume(правило)` | `{ allowed = true }` — попытка засчитана; `{ allowed = false, retry_after = секунды }` — предел исчерпан; `nil, err` — счёт не ответил |

Годится любой счёт с этим договором — в памяти узла или общий на все
узлы. Самый короткий — окно в памяти:

```lua
local clock = require('clock')

--- Предел: max попыток за минуту по ключу.
local function per_minute(max)
    return {
        by = function(_, key)
            return { key = key, max = max, window = 60 }
        end,
    }
end

--- Ограничитель в памяти узла: окно на ключ.
local limiter = { windows = {} }

function limiter:consume(rule)
    local now = clock.monotonic()
    local window = self.windows[rule.key]

    if window == nil or now >= window.ends then
        window = { count = 0, ends = now + rule.window }
        self.windows[rule.key] = window
    end

    if window.count >= rule.max then
        return { allowed = false, retry_after = window.ends - now }
    end

    window.count = window.count + 1

    return { allowed = true }
end
```

Образец помнит окно каждого имени, пока жив процесс; настоящему счёту
нужны потолок ключей и уборка, иначе перебор имён съест память узла.

Ключ счёта — имя источника и имя посетителя в нижнем регистре
(`ldap:anna`): каталог сравнивает имена без учёта регистра, и «Anna»
с «ANNA» иначе считались бы порознь. Считается каждая попытка, удачная
тоже, — одним действием `consume`, до соединения с каталогом. Пустой
пароль не считается: до каталога он не доходит. Шестая попытка за минуту
при пределе пять:

```lua
directory:authenticate('anna', 'anna-secret')
--> nil, { kind = 'throttled', message = 'попыток входа под этим именем больше предела: снова через 60 с', retry_after = 59.97 }
```

Отказ самого счёта — `unavailable`, а не пропуск без счёта: вход мимо
счёта и есть то, от чего счёт стоит перед каталогом.

### Поиск

```lua
directory:search({
    base = 'ou=groups,dc=example,dc=org',
    filter = '(uniqueMember=' .. ldap.escape('uid=anna,ou=people,dc=example,dc=org') .. ')',
    attributes = { 'cn' },
})
--> { { dn = 'cn=operators,ou=groups,dc=example,dc=org', attributes = { cn = { 'operators' } } } }
```

Поиск идёт от имени служебной учётной записи тем же соединением на один
вызов. Область — `base`, `one` либо `sub` (по умолчанию), без атрибутов —
все обычные, записей — не больше `size_limit` (по умолчанию 1000):
каталог, у которого их больше, отвечает кодом 4, и это отказ `rejected`,
а не молча обрезанный список. Ссылки на другие каталоги пропускаются.
Значение от человека — только через `escape`:

```lua
ldap.escape('*)(uid=*')
--> \2a\29\28uid=\2a
```

Негодный фильтр — бросок на строке вызова:

```lua
directory:search({ base = '', filter = '(cn=a' })
--> бросок: поиск.filter: фильтр «(cn=a»: нет закрывающей скобки
```

Фильтр — строка RFC 4515 целиком: `&`, `|`, `!`, равенство, `>=`, `<=`,
`~=`, присутствие `(cn=*)`, подстроки `(cn=an*na)` и сравнение по правилу
`(cn:dn:2.5.13.5:=Анна)`. Скобки обязательны, пустых списков `(&)` нет,
`\` — только с двумя шестнадцатеричными цифрами.

### Настройки

| Настройка | Что значит | По умолчанию |
|---|---|---|
| `url` | `ldaps://узел[:порт]` — TLS с первого байта, `ldap://узел[:порт]` — StartTLS; IPv6 — `[::1]` | обязательна |
| `base` | с какой записи искать посетителя | обязательна |
| `bind_dn`, `bind_password` | служебная учётная запись — только парой | поиск без входа |
| `filter` | фильтр с `{username}` | `(uid={username})` |
| `scope` | `base`, `one`, `sub` | `sub` |
| `subject` | атрибут опознавателя | `entryUUID` |
| `display` | атрибут имени для людей | `cn` |
| `attributes` | атрибуты в `claims` | `{ 'memberOf' }` |
| `limiter`, `limit` | ограничитель с `consume` и предел с `by` либо `limiter = false` | обязательны |
| `name` | имя источника: строчная латиница, цифры, `_`, `.`, `-`, с буквы, до 64 знаков | `ldap` |
| `timeout` | срок одного вызова, секунд | 5 |
| `tls` | `verify`, `ca_file`, `ca_path`, `sni` — как у `tnt-tls` | системные корни |

Негодная настройка — бросок на строке вызова `new`:

```lua
ldap.new({ url = 'http://ldap.example.org', base = '', limiter = false })
--> бросок: настройки.url — адрес ldaps://узел[:порт] либо ldap://узел[:порт], а не «http://ldap.example.org»
ldap.new({ url = 'ldaps://ldap.example.org', base = '', bind_dn = 'cn=reader,dc=example,dc=org', limiter = false })
--> бросок: настройки.bind_dn и bind_password — только парой: DN без пароля каталог пускает без проверки
ldap.new({ url = 'ldaps://ldap.example.org', base = '', filter = '(uid=anna)', limiter = false })
--> бросок: настройки.filter: нет {username} — искать некого
```

Сертификат каталога проверяется всегда, пока `tls.verify` не выключен
словом `false`; свой корень — `tls.ca_file` или `tls.ca_path`. Сертификат
из неизвестного корня — отказ соединения:

```lua
local unknown = ldap.new({ url = 'ldaps://127.0.0.1:18636', base = '', limiter = false })

unknown:authenticate('anna', 'anna-secret')
--> nil, { kind = 'unavailable', message = 'каталог ldaps://127.0.0.1:18636: рукопожатие TLS не прошло: рукопожатие TLS не удалось: сертификат не принят: self-signed certificate in certificate chain; error:0A000086:SSL routines::certificate verify failed' }
```

Срок — один на весь вызов: соединение, TLS, обе привязки и поиск делят
`timeout`, отмеренный монотонными часами, а каталогу поиск уходит
с пределом `timeLimit` — остатком срока, округлённым вверх.

## Отказ

Всё, что пришло снаружи, — отказ парой: `nil, err`, где `err` — таблица
с родом `kind`, текстом `message`, кодом итога LDAP `code`
и пояснением каталога `diagnostic`, если каталог их назвал, и сроком
`retry_after` у `throttled`. Строкой, в склейке и в `json.encode` отказ —
свой текст.

| Род | Когда | Ответ посетителю |
|---|---|---|
| `invalid` | пустое или длинное имя, пустой пароль, имени нет в каталоге, код 49 на пароль | 401 |
| `throttled` | попыток по имени больше предела | 429 с `Retry-After` |
| `unavailable` | сеть, TLS, срок, уведомление о закрытии, коды 3, 51, 52 (`timeLimitExceeded`, `busy`, `unavailable`), счёт попыток не ответил | 503 |
| `rejected` | каталог отказал в служебном действии: служебная привязка, поиск, StartTLS, иной код на пароль | 503 |
| `malformed` | ответ не по RFC 4511, больше записей, чем просили, имени отвечает больше одной записи, у записи нет годного опознавателя | 503 |

```lua
local down = ldap.new({ url = 'ldaps://127.0.0.1:1', base = '', limiter = false })

down:authenticate('anna', 'anna-secret')
--> nil, { kind = 'unavailable', message = 'каталог ldaps://127.0.0.1:1: соединение не открылось: Connection refused' }

-- bind_password = 'wrong': служебная учётная запись не входит
reader_with_wrong_password:authenticate('anna', 'anna-secret')
--> nil, { kind = 'rejected', message = 'каталог ldaps://127.0.0.1:18636 не пустил служебную учётную запись: код 49', code = 49, diagnostic = '' }

-- filter = '(cn={username})', у двух записей один cn
twins:authenticate('Двойник', 'twin-secret')
--> nil, { kind = 'malformed', message = 'каталог ldaps://127.0.0.1:18636: имени отвечает больше одной записи — фильтр не однозначен' }
```

Сбой каталога — не неверный пароль: 401 отправил бы человека вводить
пароль заново, а счёт попыток засчитал бы ему чужую беду.

## Проверено на настоящем каталоге

| Что | Как |
|---|---|
| `ldaps://` | вход Анны: `subject` — `entryUUID` в 36 знаков, `memberOf` и `mail` в `claims` |
| StartTLS | вход тем же паролем через `ldap://` — та же запись |
| неверный пароль и неизвестное имя | оба — `invalid`, «неверное имя или пароль» |
| разметка в имени | `*`, `*)(uid=*`, `ann*` — никого не находят |
| неоднозначное имя | фильтр по `cn`, у двух записей один — `malformed` |
| служебная учётная запись | неверный пароль — `rejected`, код 49 |
| чужой корень | сертификат стенда без `ca_file` — `unavailable` |
| поиск | группа Анны по `uniqueMember` |

## Чем пришлось поступиться

- **Соединение на один вызов, без пула.** Вход паролем меняет того,
  от чьего имени идёт соединение, и соединение после чужого входа
  пришлось бы перепривязывать; входы редки, а рукопожатие TLS на каждый
  стоит миллисекунды. Поиск тысяч записей подряд этим платит.
- **Неизвестное имя стоит обмена с каталогом.** Привязка к записи,
  которой нет, выравнивает число обменов, но не их время: каталог
  отвечает на неё быстрее, чем на настоящий пароль, который он хеширует.
- **Каждая попытка в счёте, удачная тоже.** Решение одним `consume`
  не пропускает перебор мимо счёта двумя одновременными попытками,
  а предел в пять входов в минуту удачам не мешает.
- **Ссылки на другие каталоги (referral) не посещаются**: ходить по ним
  значило бы нести пароль туда, куда его не собирались нести. Лес Active
  Directory ищут через глобальный каталог (порт 3268) одним адресом.
- **Один адрес.** Запасного каталога пакет не знает; несколько
  контроллеров за одним именем DNS пробует `socket.tcp_connect` по порядку
  адресов.
- **Группы — атрибутом.** Каталог без `memberOf` (OpenLDAP без наложения
  `memberof`) отдаёт группы только поиском `search` — его делает
  приложение. Атрибут, выданный кусками (`memberOf;range=0-1499` у Active
  Directory при полутора тысячах групп), в `claims` не собирается.
- **Только простая привязка.** SASL (Kerberos, `EXTERNAL` с сертификатом
  клиента) не поддержан, и сертификата клиента драйвер не предъявляет:
  настройка `tls` не передаёт его в `tnt-tls`.
- **Значения — байтами.** `claims` отдаёт значения как их прислал каталог;
  двоичные атрибуты (`jpegPhoto`, `objectSid`) в `json.encode` не годятся,
  и просить их в `attributes` незачем.
- **Сообщение каталога — не длиннее мегабайта.** Длина приходит раньше
  тела, и сообщение длиннее не читается: иначе чужая машина одной записью
  длины заставила бы узел копить гигабайты. Учётная запись с тысячей групп —
  около сотни килобайтов.

## Проверки

Проверки лежат в `test/` и идут на luatest. Каталог подменяется
двойником соединения: он отдаёт байты ответа кусками, как сокет,
и помнит, что ему написали, — разговор сверяется байт в байт. Ответы
каталога собираются в помощнике своей записью BER, мимо кодировщика
пакета. Подменяются сеть, TLS и часы соединения и стенные часы
удостоверения; OpenSSL двойникам не нужна.

Живая проверка `ldap_live_test.lua` идёт против OpenLDAP в докере —
TLS с первого байта и StartTLS, сертификат стенда на `127.0.0.1`:

```sh
make ldap-up        # OpenLDAP: ldaps://127.0.0.1:18636, ldap://127.0.0.1:18389
make test
make ldap-down
```

Без каталога живые проверки пропускаются: гейты не должны зависеть
от докера. Проверок — 114, из них 8 живых; покрытие строк — 100 %,
убитых мутантов — 100 % (925 мутантов в семи модулях; в фасаде
мутировать нечего).
